Why skills scale

Progressive disclosure: pay for what you use

Level 1name + description sit in context all the time. ~1 line per skill.
Level 2When a task matches, Claude reads the SKILL.md body.
Level 3Only if needed: reference files, scripts, templates in the folder.
lab-figures/
├── SKILL.md        # when + how
├── style.mplstyle  # matplotlib style
├── palette.json
└── scripts/
    └── check_fig.py # run, not read

So you can install 50 skills without slowing anything down. The description is what makes it trigger: write it like a search query.

Scripts in a skill are executed, not loaded into context, so they're context-cheap and deterministic. Good place for validation code.

You're helping me write a paper on [topic] for [venue]. Audience: [who reads it]. Notation: follow notation.md exactly. Style: plain, precise, no hype words ("novel", "groundbreaking"). A literature-review pipeline

Six steps, each with a clear owner

1 · youCriteriascope, years, study types
→
2 · ClaudeSearchResearch mode, keep a search log
→
3 · skillLit notesone per paper
→
4 · ClaudeComparetable + gaps
→
5 · youArgueyour position
→
6 · ClaudeCheckevery citation
Keep two separate sections: SEARCH LOG (queries, databases, dates, counts, what you excluded and why) and FINDINGS. Never mix interpretation into the log.
From these notes, build a table: paper · method · dataset · metric · result. Then list 3 questions none of them answers, and which paper comes closest to each.

Steps 1 and 5 are deliberately yours. Claude is a strong research assistant and a poor PI. The search log makes the review reproducible and is what a methods section needs.

⌨ TRY IT · 10 MIN

Note it, then attack it

[attach your PDF] Make a lit note of this paper.
Now act as a skeptical reviewer for [venue]. List the 5 weakest points in this paper, ranked by severity, each with: the claim, why the evidence is insufficient, and what experiment or analysis would fix it. Then tell me which of your 5 points you are least sure about.

Look for: does every claim in the note have a page reference? Can you find each quote in the PDF? The last line ("least sure about") is a cheap calibration check. Use it everywhere.

If people have the research-desk-style skills installed (paper-critique, citation-check), they can call those instead. Ask 2 people to share what the reviewer found.

Writing

Let Claude edit your thinking, not replace it

✅ Good uses

  • "Here are my bullet points; draft the paragraph, keep every claim, add nothing."
  • Highlight one sentence and ask for a fix in place (no full rewrite).
  • "Where would a reader from [other field] get lost?"
  • "Shorten by 30% without losing any number."

⚠️ Risky uses

  • "Write my introduction" from nothing: generic and confidently wrong.
  • Asking it to add citations: it will try. Use [CITE?] instead.
  • Rewriting a whole draft at once: your voice disappears.
  • Pasting reviewers' confidential manuscripts: usually a policy breach.

Edit-in-place: highlight a part of a draft and Claude edits only that spot (shipped 12 Jun 2026).

The loop

Explore → plan → do → verify

  • Explore: "Read the repo and explain how data flows from raw/ to figures/." No edits.
  • Plan: Shift+Tab into plan mode. Review, edit with Ctrl+G.
  • Do: approve and let it work.
  • Verify: tests, a rerun, a plot it compares against the old one.
~/thesis-analysis
$ claude
› The fit in fit_spectra.py gives negative widths
  on ~3% of samples. Find out why. Don't fix yet.

● Reading fit_spectra.py, data/loader.py …
● Running on the 41 failing samples …

Cause: initial guess for σ comes from FWHM of the
raw trace; with baseline offset > peak/2 the
FWHM is undefined → σ₀ = -1. Bounds aren't set,
so curve_fit walks into σ < 0.
Proposed fix: subtract baseline first, set
bounds=(0, inf). Want a plan?

The "Don't fix yet" phrasing matters: separating diagnosis from change gives far better results and lets you check its reasoning.

Permission modes

How much should Claude ask before acting?

ModeBehaviourUse when
ManualAsks before every edit and commandUnfamiliar repo, shared data, learning
Accept editsEdits files freely, asks for commandsYou're watching the diff live
PlanRead-only: researches and proposes a planAnything bigger than one file
Auto defaultA safety classifier reviews each action; risky ones are blocked or askedMost day-to-day work
BypassNo checks at allOnly inside a throwaway container

Shift+Tab cycles modes. Deny rules (e.g. never touch data/raw/) apply in every mode.

Auto mode is the default for interactive sessions since v2.1.283. It pauses after 3 consecutive blocks or 20 total. claude -p runs start in Manual since 2.1.302.

# Project: cryo-EM particle analysis
## Run
- env: `conda activate cryo` (env.yml)
- tests: `pytest -q` (must pass before commit)
- full pipeline: `make figures` (~20 min, GPU)
## Rules
- data/raw/ is READ-ONLY. Never modify or move.
- Every random op takes `seed` from config.yaml.

Skills in Claude Code

Your lab's procedures, as slash commands

# .claude/skills/run-experiment/SKILL.md
---
name: run-experiment
description: Launch a training/simulation run on
  the cluster with a logged config. Use when the
  user asks to run, launch or sweep an experiment.
argument-hint: "<config.yaml> [--sweep]"
allowed-tools: Bash(sbatch:*) Bash(git:*)
---
Current branch: !`git branch --show-current`
1. Refuse if `git status` is dirty: runs must map
   to a commit.
2. Copy $ARGUMENTS into runs/<date>-<hash>/.
3. Fill templates/job.slurm, submit with sbatch.
4. Append job id + commit to runs/LOG.md.
  • Where: ~/.claude/skills/ (personal), .claude/skills/ (repo, shared via git), or inside a plugin.
  • Call it: /run-experiment cfg.yaml, or just say "launch this config". The description makes it trigger.
  • !`cmd` injects live output into the skill before Claude reads it.
  • Skills you make in claude.ai can sync down to Claude Code.
  • Debug: /skills, /skill-doctor, /reload-skills.

Old .claude/commands/*.md files still work; custom commands have been merged into skills. Other frontmatter: model, effort, context: fork (run in a subagent), disable-model-invocation (manual only).

Hooks

Hooks are rules Claude can't forget

CLAUDE.md is advice. A hook is code that runs on an event, every time.

  • PreToolUse: block or allow an action
  • PostToolUse: format, lint, test after edits
  • UserPromptSubmit: add context to prompts
  • Stop: check work before Claude finishes
  • SessionStart, PreCompact, Notification… 33 events in all
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{ "type": "command",
        "command": "ruff format $FILE && pytest -q -x" }]
    }],
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{ "type": "command",
        "command": "scripts/guard_raw_data.sh" }]
    }]
  }
}

Easiest way to write one: "Add a hook so that after every edit, tests run." Claude edits the settings for you.

Handler types: command, http, mcp_tool, prompt, agent. A "prompt" or "agent" hook lets a model judge, e.g. "did the plot change?" Exit code 2 from a PreToolUse command blocks the action and tells Claude why. Simplified example; in real hooks, the file path arrives as JSON on stdin.

Subagents

Delegate to keep your main context clean

  • Built-in: Explore (fast read-only search), Plan, general-purpose.
  • Fork: a copy of the current conversation runs a side quest.
  • Background by default: you keep working; they report back.
  • Custom: a markdown file with its own tools, model and instructions. Manage with /agents.
# .claude/agents/stats-reviewer.md
---
name: stats-reviewer
description: Reviews analysis code and results for
  statistical errors. Use after any change to
  analysis/ or before writing up results.
tools: Read, Grep, Bash
model: opus
---
You are a methods reviewer. Check: multiple
comparisons, leakage between train/test, wrong
error bars (SD vs SEM vs CI), pseudo-replication,
seeds, and whether figures match the numbers.
Report issues by severity with file:line.
Never edit files.

Subagents get a fresh context; only their summary comes back. That's the point: 50 files of searching become 10 lines in your session. Max spawn depth and concurrency are configurable.

Research coding patterns

What actually works for scientific code

  • Tests before trust. "Write a test that reproduces Table 2 to 3 decimals, then refactor."
  • Notebook → pipeline. "Turn explore.ipynb into a script with a CLI and a config file."
  • Seeds & env. Ask it to pin versions and log the commit with every result.
  • Cluster jobs. SLURM/PBS scripts, array jobs, resubmit-on-fail.
  • Read a codebase fast. "Explain this simulation package as if onboarding a new student."
  • Figures. One skill holding the lab style. Every plot looks the same.
Before changing anything: run the current pipeline on data/sample and save outputs to /tmp/before. After your change, run it again and diff every number. Report any difference above 1e-6.

That last prompt is the golden pattern for refactoring science code: regression on numbers, not just "it runs".

The 10-line version

Messages API with structured output

import anthropic, json
client = anthropic.Anthropic()   # reads ANTHROPIC_API_KEY

schema = {"type": "object", "additionalProperties": False, "properties": {
    "organism": {"type": ["string", "null"]}, "sample_size": {"type": ["integer", "null"]},
    "method": {"type": "string", "enum": ["in vivo", "in vitro", "in silico"]}},
    "required": ["organism", "sample_size", "method"]}

msg = client.messages.create(
    model="claude-haiku-5-5", max_tokens=1024,
    system="Extract study facts. Use null if not stated.",
    messages=[{"role": "user", "content": abstract}],
    output_config={"format": {"type": "json_schema", "schema": schema}},
)
row = json.loads(next(b.text for b in msg.content if b.type == "text"))

output_config.format guarantees valid JSON matching the schema (the older output_format parameter is deprecated). In Claude Code, the built-in /claude-api skill writes this kind of code for you.

Demo tip: run this live on 3 abstracts. Then show the cost: a Haiku call like this is a fraction of a cent.

Cost levers

Same results, a fraction of the bill

🗂 Prompt caching

Reuse a long shared prefix (instructions, a codebook, a paper) across calls. Cached reads are much cheaper and faster.

📦 Batch API

Submit thousands of requests and get results within 24 h at 50% off. Ideal for coding survey data or screening abstracts.

🪶 Smallest model that works

Validate on 50 hand-labelled items. If Haiku agrees with Opus 95% of the time, use Haiku.

Pattern: screen 5,000 abstracts

Codebook in a cached system prompt → Batch API → Haiku 5.5 with a JSON schema → hand-check a random 5% → report agreement (Cohen's κ) in your methods.

Back-of-envelope: Haiku 5.5 lists at $0.10 / $0.50 per million input/output tokens (Nov 2026). 5,000 abstracts × ~400 tokens ≈ 2M input tokens ≈ $0.20, halved again by Batch. Cost is no longer the barrier; validation is.

The validation step is what makes this publishable. Reviewers increasingly ask for agreement with human coders.

Agent SDK and Managed Agents

Claude Agent SDK

The same loop, tools and context management as Claude Code, in Python or TypeScript. You run it.

from claude_agent_sdk import query, ClaudeAgentOptions

opts = ClaudeAgentOptions(
    allowed_tools=["Read", "Grep", "Bash"],
    cwd="./runs")
async for m in query(prompt="Which runs diverged? Why?",
                     options=opts):
    print(m)

Managed Agents beta

Anthropic hosts the agent loop and a sandbox for you. Caching and compaction are built in. Good when you don't want to run infrastructure.

Build an MCP server

Wrap your instrument, simulator or database in ~30 lines (Python FastMCP). It then works in Claude Code, the apps (as a custom connector) and your agents.

Managed Agents launched in public beta in April 2026. Outcomes, multiagent and memory features are in research preview. The SDK example is the async iterator pattern; wrap in asyncio.run.

What goes wrong, and the habit that catches it

FailureGuardrail
Plausible but fake citations[CITE?] placeholders; verify every reference against DOI/arXiv (a citation-check skill helps)
Confident wrong math or statsMake it compute in code, not in prose; reviewer subagent; "what are you least sure of?"
Silent data changesRaw data read-only via deny rules or hooks; git everything; diff numbers before/after
Agreeing with you (sycophancy)Ask it to argue the other side; don't reveal your preferred answer first
